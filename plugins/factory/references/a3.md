# The A3: one problem, one experiment, one reading

For the lead. Read it at step 9 and whenever an override is written. Roles do not read it.

One A3 per run: one problem, at most one experiment, one reading of what moved. The baseline (`references/baseline.md`) is the page of what normal looks like; the A3 is the report of one run.

## 1. Where it is, how it is found, posted and edited

- **One comment per run, on the run's map issue `#<map>`** in the project's own tracker. Never in `WimSuenens/agent-plugins`; No command here names `--repo`.
- **Marker.** The body's first line is exactly `<!-- factory:a3 v1 -->`. A reader finds an A3 by `^<!-- factory:a3 v([0-9]+) -->$` on the first line; a reader that meets a version it does not know skips the comment and says so.
- **Commands**: *Find A3*, *Post A3*, *Edit A3* in `## Factory operations`.
- **Posted once at the run close, step 9.2.** When *Find A3* finds one:
  - its `answer` line reads `pending` for every entry (an interrupted close): rewrite the comment with *Edit A3* (the same fields, recomputed);
  - an answer is already recorded: the run's A3 is settled and no second one is written; say `A3 for run #<map> is already settled: <URL>.` The items closed after it are read through the baseline.
- **After the settle**, edit the `answer` line only.
- **No A3 for a run with no closed item**: say `0 items closed: nothing to measure` and post nothing. A run is empty when the Factory run section's `closed in this run` line is absent or empty.
- **A run the person stops after at least one item closed** gets its A3 (after the person's one yes, step 9); the `run:` line reads `run stopped`. "First line" in the criteria is the first field line, the body's first line being the marker.
- **Content rules.** `problem`, `evidence`, the 5 Whys causes and every list are your **paraphrase**: no raw hansei record, transcript text, secret, absolute or home path, or instruction-like sentence is copied; point to where the text is (an item number, a comment URL, `file:line`). It names the baseline issue by link. It is posted in English.

## 2. The template

Fixed lines, fixed order, **no line may be left out**; a line with nothing to say reads `none (<reason>)`. Angle brackets are filled in.

```
<!-- factory:a3 v1 -->
## A3: run #<map> <map title>

- run: #<map> — <closed | run stopped>
- series and release: <M.N>; factory <semver>; standard <64 hex>; tooling <64 hex>
- problem: <one sentence in factory terms | none chosen (<reason>)>
- evidence: <what was counted, with item numbers and links | none>
- 5 whys:
  1. Why …? — <cause naming a process object> — evidence: <file:line | URL | timestamp | sha>
  …
  process item to change: <one missing, unclear or unenforced rule>
- process item to change: <the same text as the chain's last line | none>
- countermeasure: <override name (started YYYY-MM-DD) | none (<reason>)>
- measure targeted: <number field — direction down|up | none (<reason>)>
- before: <reading | none (<reason>)>
- after: <reading | none (<reason>)>
- change: <signed difference — toward|against the intended direction (down|up) | 0 — no change | not comparable (<why>) | not captured (<reason>) | none (<reason>)>
- items counted: before <#a, #b | none>; during <#c | none>; after <#d, #e | none>
- still uncertain: <section 8>
- other problems seen: <section 4 candidates, each with its count | none seen>
- other overrides: <name: before/after: not measured (not this run's experiment); … | none>
- standard changes proposed: <plugin change: … | other abnormality A<k>: …; … | none>
- baseline: <URL of the Factory baseline issue>
- answer: <name (experiment): pending | …; name: pending | none (no override to settle)>
```

- `series and release`: the series of the run's last closed item and the label of that item's record (`release`, `standard`, `tooling`).
- **A reading** is `<value> (<k> of <n>; items #<a>, #<b>; factory <semver>[, <semver>])`: the value read as `references/baseline.md` section 4 R1 (a median), `k` the items that captured the field, `n` the items counted, the item numbers, and the release(s) of those items. Other forms: `not captured (<reason>)` (no value; `k = 0`), `n/a (did not run in any of <n> items)`. A reading never has a blank, and never `0` for a value not measured.
- **`change`** is the after median minus the before median in the measure's unit (`+4m`, `-1`, `-12000`), then ` — toward the intended direction (<down|up>)` when the sign matches the direction, ` — against the intended direction (<down|up>)` when it does not, and the bare `0 — no change` for a measured zero difference. It is never written for readings that are not comparable (section 7).
- **The 5 whys** follow the one rule in `skills/run/SKILL.md`, *The 5 Whys*, and **the A3 text does not restate it**: it points to that section, so one change edits both. A refused chain is not posted. With no problem (`none chosen`), the block reads `- 5 whys: none (no problem chosen)` on one line.
- **`still uncertain`** is never empty (section 8).
- **`other overrides`**: every other override written or in force in the run, one entry each: `<name>: before/after: not measured (not this run's experiment)`; `none` when the run wrote or applied no other.
- **`standard changes proposed`**: each plugin change an andon proposed (`plugin change: <one line>`) and each `other` (kind 7) abnormality of the run (`other abnormality A<k>: <problem in factory terms>`), plus the experiment's proposal when its only form was a plugin change. Step 9.4's drafts are written only from this line and the person's remark.
- **`answer`**: one entry per override the settle round asks about (not the `promote chosen` ones), the experiment first and marked `(experiment)`, then the others in file order. `pending` until the person answers; then `keep <YYYY-MM-DD>`, `promote <YYYY-MM-DD>` or `drop <YYYY-MM-DD>`. Grammar of an entry: `^[a-z0-9]+(-[a-z0-9]+)*( \(experiment\))?: (pending|(keep|promote|drop) [0-9]{4}-[0-9]{2}-[0-9]{2})$`. The baseline reads the `drop` entries.

**Allowed reasons after `none (…)`** on `countermeasure`, `measure targeted`, `before`, `after` and `change` (the same reason on all five):

| Reason | When |
|---|---|
| `no closed item in series <M.N> to measure against` | the run had no readable closed item in the current series when the countermeasure was decided |
| `needs a plugin change` | the countermeasure's only form is a change of plugin text; nothing is written in `docs/agents/factory.md` |
| `no measure with a captured before-reading` | no allowed measure (section 5 item 4) has `k >= 1` in the reference section |
| `refused at the fence (<fenced item>)` | the fence check refused it |
| `no problem chosen` | section 4 ended in `none chosen` |
| `no countermeasure was tried` | a problem was chosen and no countermeasure was written |

There is no line keyed `experiment` in the A3: "no experiment" is the `countermeasure:` line's `none (<reason>)`.

## 4. Rule: the run's one problem

**When it is applied.** At two moments, with the same rule: (a) **when a countermeasure is about to be written** (an andon's step 4, or between items), over the run's andons and items so far; the problem it picks is the one the run's experiment targets (section 5); (b) **at the run close**, when no experiment was written, to fill the A3's `problem`. When an experiment exists, the A3's `problem` is the experiment's problem (frozen at (a)); the rule is applied again at the close only to list the other candidates and their counts.

**The run's andons** are the andon comments linked in the `abnormalities` line of the records of the run's items (the run list: the Factory run section's `closed in this run`) and, at moment (a) inside an item, the rows of that item's `## Abnormalities`. A hansei `abnormalities` entry without a comment (`raised, no andon recorded`) is not a candidate.

1. **Candidates from andons.** For each andon of the run take its `process item to change:` line (the last line of its 5 Whys). Reduce it to a **target**: the first token that looks like a file path (letters, digits, `_`, `.`, `/`, `-`, ending in `.md`, `.sh` or `.json`); failing that, the first token that begins `## ` (a section heading); failing that, the whole line in lower case with runs of spaces collapsed. **Two andons name one candidate when their targets are equal.** Its **count** is the number of distinct items of the run that hold at least one andon with that target. Its **first raised** is the earliest `raised at:` among its andons.
2. **The problem** is the candidate with the largest count; a tie goes to the one raised first. Every other candidate is listed in the A3's `other problems seen` as `<target>: <count> item(s)`. There is one problem, never two.
3. **With no andon in the run:** the candidates are the **numeric fields** of the reference section (the fields of the table in section 5 item 4; measure 2 is not a candidate) that have `k >= 1` and a median above 0 in the reference section as it stood **before the run's first item** (`base`) and `k >= 1` among the run's items (`run`). Each candidate's **ratio** is the run's median (R1 of `references/baseline.md` section 4, over the run's items in the current series) divided by `base`. The problem is the candidate with the **largest ratio**; a tie goes to the field earlier in the field list of `references/baseline.md` section 4. The A3 appends `not above baseline` to the problem line when that ratio is 1 or less. Every other candidate **with a ratio above 1** is listed in `other problems seen` as `<field> ×<ratio to two decimals>`; those at or below 1 are counted in one entry, `<n> others at or below baseline`.
4. **When no candidate exists** (no andon, and no field with a base): the problem line reads `none chosen (no baseline reading to compare with)`, or `none chosen (no closed item)` when nothing closed. That is a stated end of the rule, never a silent `none`.

**Reading.** Three items: A1 (target `plugins/factory/agents/qa-engineer.md`) in items 1 and 2, A2 (target `plugins/factory/skills/run/SKILL.md`) in item 3 give candidates A1 (2 items) and A2 (1 item); the problem is A1, and A2 is listed `…SKILL.md: 1 item`. Two andons with the same file in item 1 count 1. With no andon, lead time total 30m against a base median 18m gives ratio 1.67; if every other field is 1.00 or lower it is the problem, with `other problems seen: <n> others at or below baseline`.

## 5. The experiment: one override that names its measure

**The run has at most one experiment.** The first override the run writes that meets **all** of the following is the experiment; every later or other override is listed under `other overrides` as `not measured (not this run's experiment)`.

1. **Fence first.** The eight questions of the protocol's *Never overridable locally* are asked of its effect before anything is written. One yes refuses it: nothing is written, the A3's reason is `refused at the fence (<fenced item>)`.
2. **A closed item to measure against.** The current series has at least one readable closed item in its reference section (`n >= 1`). Otherwise the countermeasure is still written when an andon needs it, but it is **not** the experiment: the A3 reads `none (no closed item in series <M.N> to measure against)` and the first items measure only.
3. **It addresses the problem.** The countermeasure's process item is the problem chosen by section 4 at this moment (its target equals the problem's). An override for any other process item is not the experiment.
4. **It names one measure** from the table below whose reference reading has `k >= 1`, and a direction; take the measure the process item would move first (guide, not a rule: a missing line in a brief or a repeated finding moves `3 <role>` down; a slow stage moves `1 agent working` down). Write the `before:` reading over the before-items (section 6). With no such measure: `none (no measure with a captured before-reading)`, and the override, if an andon needs it, is not the experiment. **An experiment is never written with `before: not captured`.**
5. **Its form is an override.** A countermeasure whose only form is a plugin change writes no override: the A3 reads `none (needs a plugin change)`, the proposal goes in `standard changes proposed` and, if the person approves a draft, in step 9.4's issue. No path under `plugins/` ever changes to apply a countermeasure.

The allowed form of `measure:` is `<number> <field>`:

| Measure | `<field>` | Unit |
|---|---|---|
| 1 lead time | `total`, `agent working`, `waiting for the person`, `waiting on limits`, `stalled`, `interrupted`, `andon` | minutes |
| 3 rework | a role (`product-owner` … `docs-writer`) or `overturned` | count |
| 5 tokens | `<role> spend` or `<role> peak context` (`lead` included) | tokens |
| 6 person's touches | `decision cards`, `demos`, `approvals`, `overturns`, `other` | count |

Each is read as a median. Measures 2, 4 and 7 are not allowed (an outcome, a constant, outcomes per line). An experiment that names a measure outside this table is not written.

**The experiment's lines.** The experiment's override carries eight more lines after `fence check` (format in `skills/run/SKILL.md`, *Overrides*), written at the moment the override is written and never edited except `a3`. They go in the same commit that writes it: `#<id> lead: override <name>`. Written between items, the commit is made in the worktree of the next item; written by an andon, in the item's. Its `andon` line reads `none (experiment)` when no andon started it.

## 6. Before, during and after

Let the experiment be `X` with `series`, `reference` (`R0`, the set of names) and `before` frozen in the override. Let **the run list** be the items in the Factory run section's `closed in this run`. Take every readable record (`references/baseline.md` section 3) and classify each:

1. **Other series, calibration, excluded** (a record in no section of `series`, or excluded by `references/baseline.md` section 3): in **no reading**. Records of the run that sit in another series are noted in section 7.
2. **During-item:** the record carries `X` with extent `from` or `until`. Named in `items counted` (`during`), counted in neither reading.
3. **After-item:** the record is in the run list and carries `X` with extent `whole item`.
4. **Before-item:** the record is in series `series`, carries no `X`, has no partial override of any name, and its key equals `R0`.
5. Any other record is in no reading (for example a key that differs from `R0`).

**The readings.** `before` is the reading of `references/baseline.md` section 4 for the measure over the before-items, as in the override's `before:` line (recompute it at the close; a difference from the stored line is named in `still uncertain`). `after` is the same reading over the after-items. Each names its `k`, `n`, the item numbers and the release(s). A during-item, a calibration item or an other-series item is never counted.

**Reading.** Series `1.2`, `X` written at 14:20Z: a record (no `X`, key `none`, closed 13:00Z) is a before-item; a record with `X (since …; from 14:20Z)` is a during-item; a record with `X (…; whole item)` in the run list is an after-item; a similar record of series `1.3` and a calibration record are in no reading.

## 7. When the two readings cannot be compared

Apply in this order; the first that holds decides `change`. Each side (`before`, `after`) is always shown as it is.

1. **No after-item** (`n = 0`): `after` reads `not captured (no after-item: no item closed in this run with <name> in force for the whole of it)`; `change` reads `not captured (no after-item)`.
2. **The release moved.** Some after-item's series differs from `series`: `change` reads `not comparable (release moved from <series> to <series list>)`. The `after` reading is over those items with their release.
3. **Another override on one side only.** For each after-item compute its key minus `{X}`. If it differs from `R0`: `change` reads `not comparable (override <Y> in force for the after-items only)` for each name in the key not in `R0`, and `(override <Y> not in force for the after-items)` for each name in `R0` not in the key.
4. **The role or stage did not run.** The after reading is `n/a (did not run in any of <n> items)`: `change` reads `not comparable (the role did not run in the after-items)`.
5. **No captured value.** The after reading has `k = 0` (`m >= 1`): `change` reads `not captured (<the after reading's reasons>)`. Never `0`, never a difference.
6. Otherwise `change` is the signed difference of section 2. It is **never** computed for readings that fail 1 to 5.

A difference is never shown between readings that are not comparable, and `0` never stands for a value not captured.

## 8. `still uncertain`

The line is **never `none` and never empty**. It holds these clauses, in order, separated by `; `:

1. `sample: before <k> of <n> items, after <k> of <n> items`; a count of 1 reads `one item`.
2. `other overrides in force during the after-items: <names | none>`.
3. `kind of work: <named>`: the kind (the slices' titles' common kind, in neutral words) and whether the before-items and after-items were alike.
4. `not captured in the readings: <each field and item the readings hide, with its reason | none>`.
5. `no significance is claimed: these are counts with item numbers, what moved and not that it is proven`.

With `none (<reason>)` readings, clause 1 reads `sample: no reading`.

## 9. The check before *Post A3*

Do not post an A3 whose `before`, `after` or `change` line is blank, missing, or `0` for a value that was not measured. A run with no experiment posts `before`, `after` and `change` as `none (<reason>)` with a reason from section 2's table.
