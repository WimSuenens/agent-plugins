## Findings

### F1 — AC-8 — major, blocks — frontier round opens a PR without the bump check

- Location: `plugins/factory/skills/run/SKILL.md` step 3, end of round, item 2: "Open one PR from `frontier/<map>` carrying only ADRs and glossary changes."
- Reproduction: `bash tests/factory/test_standard_text.sh` → `skip ac8-no-pr-without-check -- QA-39 F1 … SKILL.md:82`. Or: `grep -nE 'gh pr create|[Oo]pen (one |the )?PR' plugins/factory/skills/run/SKILL.md`. The check paragraph sits in step 6 and covers only the item's *Open PR*.
- Expected (AC-8): "It is contradicted if any instruction in the standard opens a PR without passing this check first." The developer's own text says "No instruction anywhere opens a PR without this check."
- Actual: the frontier round's PR has no check. A frontier round that touched `plugins/factory/` (against its own rule, or through a stray commit) would reach `main` with no bump.
- Fix (developer, one line): in step 3, item 2, run the *Open PR* bump check (same exit handling) before opening the round's PR. In a project without `plugins/factory/`, and for an ADR-only round, it passes at once (tested: ac10-*).

### F2 — contract 39-plugin-scripts §1, AC-16 spirit — minor, does not block — unreadable standard file gives a fingerprint as if captured

- Reproduction: copy the plugin tree, `chmod 000 references/hansei.md`, run `fingerprint.sh` on it. Test: `test_fingerprint.sh` `unreadable-file-fails` (skip).
- Expected: a non-zero exit (the Lead then writes `not captured (<message>)` in `## Label`).
- Actual: "Permission denied" on stderr, then exit 0 and a `standard:` value that hashes empty content for that file.
- Fix (developer): fail (exit 2 or a new code) when a file in either set can't be read. Unlikely in a real plugin cache, so not blocking.

### F3 — contract 39-plugin-scripts §1 — minor, does not block — `"version": ""` reads as a pre-release install

- Reproduction: `plugin.json` with `"version": ""`, run `fingerprint.sh`. Test: `test_fingerprint.sh` `empty-version-exit-2` (skip).
- Expected: exit 2 (a `version` that isn't `MAJOR.MINOR.PATCH`).
- Actual: exit 0, `release: <dir> (pre-release install, no semver)`, so a record would read `series: calibration` instead of failing.
- Fix (developer): tell an empty `version` apart from a missing one. `check-bump.sh` already refuses an empty new version.

### Observations (no finding)

- `token-spend.sh`: when the input is valid JSON but the wrong shape (an array line, a non-date `timestamp` inside a window), exit 3 is right, but stderr reads `transcript unreadable` with no file name. The Lead's value then lacks the name `hansei.md` asks for.
- `token-spend.sh`: options must come before the files. `… file.jsonl --since T` treats `--since` as a file and exits 3.
- `check-bump.sh`: a version with a leading zero (`1.08.0`, not valid semver) triggers a bash octal error and an empty `(suggested)`. It still refuses with exit 1.
- `references/hansei.md` writes script calls as `bash "${CLAUDE_PLUGIN_ROOT}/scripts/…"`. A reference file is read, not loaded as a skill, so the variable is not substituted there. The Lead must take the root from the `Plugin root:` line in the run skill, as both files say. The demo should watch for this (prep check 2).
