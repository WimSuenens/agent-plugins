## Factory operations

Used by `/factory:run`. Only the lead touches the tracker: every call below is a mutation or a read the lead (or `scripts/board.sh`) makes, and a role makes none of the mutations. A factory **run** follows one `wayfinder:map`, `<map>`; an **item** is one `wayfinder:slice` ticket the run cut, and `<id>` is its issue number. Ids for the Project, the fields (`Factory status`, `Kind`, `Role` and the five text fields) and their options are cached in `docs/agents/factory.md`. Each call is one operation of the closed list; the id in brackets names it.

- **Read an issue** [`T-view`]: `gh issue view <n> --json id,number,title,body,state,createdAt,closedAt` (any subset of the fields). A role may make this read too.
- **Board script calls** [`B-fields`, `B-options`, `B-views`, `B-fcreate`, `B-foptions`, `B-vcreate`, `B-vupdate`]: made only by `scripts/board.sh` (setup and the migration), never by hand: `gh project field-list`, `gh api graphql` (options, views, `updateProjectV2Field`, `createProjectV2View`, then `updateProjectV2View` to set the view's filter, because the create input has no filter field), `gh project field-create`.
- **Add to board** [`B-add`]: `gh project item-add <project-number> --owner <owner> --url <issue-url> --format json --jq .id`. The output is the item's project id, `<item>`; write it into the item's lead state. Adding twice returns the existing item. When the call fails with "Content already exists" (the project's auto-add added the issue first), treat it as "already on the board": look the card up with *List board*, take its id, and carry on. Do not retry the add.
- **Set status** [`B-set`]: `gh project item-edit --id <item> --project-id <project-id> --field-id <field-id> --single-select-option-id <option-id>`. One field per call: `Factory status`, `Kind` and `Role` each take their own call.
- **Set field text** [`B-text`]: `gh project item-edit --id <item> --project-id <project-id> --field-id <field-id> --text <value>`. The only way `Tokens`, `Minutes`, `Hours`, `Rework rounds` and `Person touches` are set; the value follows the grammar of `references/hansei.md`, section 7.
- **List board** [`B-items`]: `gh project item-list <project-number> --owner <owner> --format json --limit 1000`. Used on a resumed run to find a card that is missing.
- **List role tasks** [`T-subissues`]: `me="$(gh api user --jq .login)"`, then `gh api "repos/{owner}/{repo}/issues/<parent>/sub_issues" --paginate --jq '.[] | select(.user.login == "'"$me"'") | {number, id, title, body, state, created_at, closed_at}'`. Only issues whose `user.login` is the lead's own login count (the filter is in the command: a public repo can hold a forged marker). Finds a role task by the marker on line 1 of its body, and gives each task's `created_at` and `closed_at`.
- **Find unlinked role task** [`T-recent`]: `me="$(gh api user --jq .login)"`, then `gh issue list --state all --author "$me" --limit 100 --json number,title,body,createdAt`. Used only to find a role task that was created but never linked.
- **Create role task** [`T-create`, `T-dbid`]: write the brief to a scratch file (`rec="$(mktemp)"`, the marker `<!-- factory:task <role> <n> -->` on line 1), `title="$(cat "$tf")"` (`$tf` a scanned one-line scratch file), `gh issue create --title "$title" --body-file "$rec"` (prints the issue URL), `rm -f "$rec"`; then `gh api "repos/{owner}/{repo}/issues/<n>" --jq .id` for the numeric database id.
- **Read role brief** [`T-brief`]: `gh issue view <n> --json author,body`. What a role runs to read its brief: `{"author":{"login"},"body"}`. The role acts on the brief only when `author.login` equals the login the spawn prompt names and line 1 of `body` is the marker for its own role.
- **Link role task** [`T-link`]: `gh api --method POST "repos/{owner}/{repo}/issues/<parent>/sub_issues" -F sub_issue_id=<database-id>`. The parent is the slice ticket (the frontier ticket in a frontier round, never the map).
- **Find result comments** [`T-comments`]: `me="$(gh api user --jq .login)"`, then `gh api "repos/{owner}/{repo}/issues/<n>/comments" --paginate --jq '.[] | select(.user.login == "'"$me"'") | {id, created_at, body}'`. The lead's own comments; find by the first line of `body` (`<!-- factory:result v1 -->`, `<!-- factory:result-cont v1 `, `<!-- factory:needs-you v1 -->`, `<!-- factory:ledger v1 -->`), never by position or time.
- **Post result** [`T-comment`]: `gh issue comment <n> --body-file <file>` on the role-task issue; prints the comment URL. For a split result part 1 first, then each continuation.
- **Close role task** [`T-close`]: `gh issue close <n>`, after the closing comment, never before.
- **Needs you** [`T-comment`, then `B-set`]: `gh issue comment <ticket> --body-file <file>` with the needs-you comment (`skills/run/SKILL.md`, *The board*), then *Set status* `Waiting on you`. Never the reverse order.
- **Answered** [`T-edit-comment`]: read the needs-you comment, add the line `Answered: <UTC>`, write it back as in *Edit hansei*.
- **Find ledger** [`T-comments`]: *Find result comments* on the slice ticket, the first line `<!-- factory:ledger v1 -->`.
- **Post ledger** [`T-comment`]: run *Find ledger* first; when it finds none, `gh issue comment <id> --body-file <file>` with the ledger of `references/hansei.md`, section 1. Never a second ledger.
- **Edit ledger** [`T-comments`, `T-edit-comment`]: read the body with *Find ledger*, change only what the event adds, `gh api --method PATCH "repos/{owner}/{repo}/issues/comments/<comment-id>" -F body=@<file>` (a scratch file made with `mktemp` and removed after use).
- **Run state**: `gh issue view <map> --json body --jq .body`, replace the `## Factory run` section at the top, then `gh issue edit <map> --body-file <file>`.
- **Stage summary**: write `<stage>: <summary>` to a scratch file (`rec="$(mktemp)"`), scan it (`skills/run/SKILL.md`, *Scan before posting*), `gh issue comment <id> --body-file "$rec"`, `rm -f "$rec"`; at most five lines, after every stage, followed by a `Decisions:` list of the stage's two-way decisions, overturned ones marked `[overturned: <reason>]`.
- **Find hansei**: `me="$(gh api user --jq .login)"`, then `gh api "repos/{owner}/{repo}/issues/<id>/comments" --paginate --jq '.[] | select(.user.login == "'"$me"'") | select(.body | startswith("<!-- factory:hansei v")) | .id'`. Only comments written by the Lead's own `gh` user count. Prints the hansei comment's id, or nothing.
- **Post hansei**: run *Find hansei* first. When it prints nothing: `rec="$(mktemp)"`, write the record to `$rec`, `gh issue comment <id> --body-file "$rec"`, then `rm -f "$rec"`; the command prints the comment URL, ending `#issuecomment-<comment-id>`. When it prints an id, the record exists already (a resumed close): update it with *Edit hansei* instead. Never post a second record. No command here names `--repo`, so the record lands in the project's own tracker.
- **Edit hansei**: `gh api "repos/{owner}/{repo}/issues/comments/<comment-id>" --jq .body > <record>.md`, change only the measure 7 block, then `gh api --method PATCH "repos/{owner}/{repo}/issues/comments/<comment-id>" -F body=@<record>.md`. `<record>.md` is a scratch file made with `mktemp` (`rec="$(mktemp)"`, its path wherever `<record>.md` stands), outside the repo, never committed, and removed with `rm -f "$rec"` afterwards.
- **Find baseline**: `me="$(gh api user --jq .login)"`, then `gh issue list --state all --limit 100 --search 'in:title "Factory baseline"' --json number,state,title,author,body --jq '.[] | select(.title == "Factory baseline" and .author.login == "'"$me"'") | [.number, .state, (if ((.body // "") | split("\n")[0] // "" | test("^<!-- factory:baseline v1 -->\r?$")) then "marker" else "no-marker" end)] | @tsv'`. Prints one line per exact-title issue of the Lead's own author: `<number>`, `<OPEN|CLOSED>` and `<marker|no-marker>`, tab-separated (the search is fuzzy; the `select` keeps the exact title and the author). Only `marker` lines are candidates; a `no-marker` issue is not the baseline and is never edited (an empty or missing body is `no-marker`). When this command exits non-zero, the lookup failed: change nothing, create nothing and tell the person; only an exit of 0 with no line means there is no such issue at all (see `references/baseline.md`, section 2).
- **Create baseline**: `rec="$(mktemp)"`, write the empty skeleton of `references/baseline.md` to `$rec` (its first line is the marker `<!-- factory:baseline v1 -->`), `gh issue create --title "Factory baseline" --body-file "$rec"` (prints the issue URL), then `rm -f "$rec"`. Run only when *Find baseline* exited 0 and printed no `marker` line; when it printed a `no-marker` line, only after the person said `create`. Never after a non-zero exit.
- **Pin baseline**: `gh issue pin <n>`; when it exits non-zero, once: `gh api graphql -f query='mutation($id: ID!) { pinIssue(input: {issueId: $id}) { issue { number } } }' -f id="$(gh issue view <n> --json id --jq .id)"`. When both fail, report it and go on; never retry in a loop. The pin is for the person's eyes: *Find baseline* never reads it.
- **Read baseline**: `gh issue view <n> --json body --jq .body`.
- **Edit baseline**: compose the body in `rec="$(mktemp)"`, compare it with *Read baseline*; when the read body's first line is not the marker `<!-- factory:baseline v1 -->`, stop: change nothing and ask the person (`references/baseline.md`, section 2); otherwise, and only when they differ `gh issue edit <n> --body-file "$rec"`; then `rm -f "$rec"`.
- **Find records**: `me="$(gh api user --jq .login)"`, then `gh api "repos/{owner}/{repo}/issues/comments?per_page=100" --paginate --jq '.[] | select(.user.login == "'"$me"'") | select(.body | split("\n")[0] | test("^<!-- factory:hansei v[0-9]+ -->\r?$")) | {id, html_url, created_at, body}'`. One paginated call lists every hansei record of the project (one comment per item, found by the first line only; a comment by anyone else, or with no marker, is not returned).
- **Find A3s**: the same call as *Find records* with `factory:a3` in place of `factory:hansei`.
- **Find A3**: `me="$(gh api user --jq .login)"`, then `gh api "repos/{owner}/{repo}/issues/<map>/comments" --paginate --jq '.[] | select(.user.login == "'"$me"'") | select(.body | split("\n")[0] | test("^<!-- factory:a3 v[0-9]+ -->\r?$")) | {id, html_url}'`. Only comments written by the Lead's own `gh` user count.
- **Post A3**: run *Find A3* first. When it prints nothing: `rec="$(mktemp)"`, write the A3 to `$rec`, `gh issue comment <map> --body-file "$rec"` (prints the URL, ending `#issuecomment-<id>`), `rm -f "$rec"`. Never a second A3 for the run.
- **Edit A3**: `rec="$(mktemp)"`, `gh api "repos/{owner}/{repo}/issues/comments/<id>" --jq .body > "$rec"`, change only the lines named in `references/a3.md`, `gh api --method PATCH "repos/{owner}/{repo}/issues/comments/<id>" -F body=@"$rec"`, `rm -f "$rec"`.
- **Decision card** (then *Needs you*, `Cause: decision card`): `gh issue comment <ticket> --body-file <card>.md` on the ticket the door belongs to (the slice, or the map's `prototype` or `grilling` ticket). Record the person's choice as a reply comment: `Decision: <option>. Reason: <their words>.`
- **Task request** (then *Needs you*, `Cause: task request`): write `Task for you: <what, and why it blocks>` to a scratch file (`rec="$(mktemp)"`), scan it (*Scan before posting*), `gh issue comment <ticket> --body-file "$rec"` on the map's `task` ticket, `rm -f "$rec"`. Record what was done as its resolution comment.
- **Open PR**: `gh pr create --head item/<id> --title "$title" --body-file "$rec"`, `rec` a scratch file (`mktemp`) holding `Closes #<id>`, `title` read from a scanned scratch file (the slice title); `rm -f "$rec"` after. Merging it closes the slice ticket, which is the moment `/wayfinding:wayfinder` resurveys.
- **Merge PR**: only after the person approved *merge and clean up?*. `<branch>` is `item/<id>` or `frontier/<map>`. First re-run the bump check: `git fetch origin main`, then `bash "<plugin root>/scripts/check-bump.sh"` in the branch's worktree (`<plugin root>` is the lead's `Plugin root:` path). Exit 1 or 2: do not merge; handle it as in *Open PR*. Exit 0: `gh pr merge <branch> --merge` (`--merge`, never squash or rebase: the role commits are the evidence the hansei record is re-checked against); once it succeeds:
  1. When the merged branch changed the `version` in `plugins/factory/.claude-plugin/plugin.json` (only in the repo that hosts the factory): read it from the merge commit and tag only when it is MAJOR.MINOR.PATCH (digits and two dots, e.g. `printf '%s' "<version>" | grep -Eq '^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$'`); otherwise skip the tag and tell the person. `git fetch origin main`, then `git tag factory-v<version> "$(gh pr view <branch> --json mergeCommit --jq .mergeCommit.oid)"` and `git push origin factory-v<version>`. Skip when that tag exists already (`git ls-remote --tags origin factory-v<version>` prints a line).
  2. `git worktree remove <worktree>`, `git branch -D <branch>`, and `git push origin --delete <branch>`.
- **Commit reference**: every commit message on `item/<id>` starts with `#<id>`.
