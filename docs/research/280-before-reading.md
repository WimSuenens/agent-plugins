# Can the before-reading be reconstructed from past runs?

Answers [#280](https://github.com/WimSuenens/agent-plugins/issues/280), part of [#278](https://github.com/WimSuenens/agent-plugins/issues/278) (the Obeya discipline). The question: for each past factory run in this repo, can the existing artifacts give the **run start**, the **run close**, the **raw elapsed duration**, and the intervals in which the **whole run** was blocked waiting on the person or on a session/usage limit (no other run work going on)? A wait on one item while other run work continued is not a run block.

Honesty rule: a value that could not be read is `not captured (<reason>)`, never 0 and never a guess. Times are UTC. Data was read on 2026-11-27 from the tracker with `gh` (issue bodies, body edit history through GraphQL `userContentEdits`, comments, role-task sub-issues) and from the repo.

## What the contracts let us read

- **Run start.** Only since factory 3.3.0 (#230, `scripts/run-state.sh start`) does a Factory run section carry a `started:` line ([run-overrides.md](../../plugins/factory/references/run-overrides.md), *Run identity*). Before that, no field holds the run start; the best proxy is the body edit that first wrote the run's Factory run section (GitHub edit history), or the earliest run artifact. Both are later than the true start: the steps before (charting the map, step 0 to step 4) leave no timestamp.
- **Run close.** The A3 comment's `created_at` ([run-close-run.md](../../plugins/factory/references/run-close-run.md) step 9.2; the `- A3:` line marks the run closed). Neither the A3 (v1 to v3, [a3.md](../../plugins/factory/references/a3.md)) nor the Factory run section has a close-time field; the comment time is the reading.
- **Waits.** Only inside an item: the ledger's Waits table (kinds `person`, `limits`, `stalled`, `interrupted`, `andon`; `Held item` yes/no) and the hansei record's measure 1 totals ([hansei.md](../../plugins/factory/references/hansei.md)). `Held item: yes` means no role agent *of that item* worked; it says nothing about other items in flight or about the lead. Role-task times are the sub-issues' `created_at`/`closed_at`.
- **Person waits outside items.** Only needs-you comments (`<!-- factory:needs-you v1 -->`, `Asked:`/`Answered:`), which exist from factory 2.x on. Questions the lead asks in the session (which slice next, close the run now?) leave no record unless they become a card.
- **Limits outside items.** Nothing: the close scan (`cut-offs.sh`) runs over the transcripts of an item, not over the lead's time between items or in a frontier round.
- **Before 2.0.** Factory 1.x kept waits in the lead state (`work/<id>/00-lead-state.md`), removed at item close; hansei v5 on 1.3.0 keeps only totals. The 1.x calibration run kept manual stage logs as plain comments.

Method for a whole-run block: take each item's ledger wait with `Held item: yes`, intersect with the time in which no other item of the run had an open role task (sub-issue) or an unheld stretch, and add frontier-round needs-you intervals minus open role-task intervals. What this cannot see is the lead's own work outside items (cutting a slice, rebasing, reading CI); such an interval is reported as a *candidate*, not a block.

## Sample count

- **Usable runs: 4** (R3, R4, R6, R8), **partially usable: 3** (R2 totals only, R5, R7), **not usable: 1** (R1, calibration).
- The four usable runs are in **four different series** (2.0, 2.2, 3.2, 3.4): **n = 1 per series**. Every one of them is a single-item run, where a whole-run block is simply the item's held wait; none tests the parallel case.
- **The latest series with any run is 3.4**: 1 usable (R8) and 1 partial (R7). The factory on main is 3.9.0; no run has been made on 3.5 to 3.9, so the series the preview will ship next to has **0** samples. Under the baseline's carry-over rule ([baseline.md](../../plugins/factory/references/baseline.md) section 6, item 6) an older series whose `standard` changed is *indicative* only and never the "before" of an experiment; 3.4 to 3.9 changed the standard.

## Verdict

**Partially reconstructable, and not enough for a before-reading.** Run close is readable for every run since the A3 existed (the A3 comment time), but run start is a field only since 3.3.0, and even on 3.4 one of two runs (#146's third run) skipped it; earlier starts are body-edit proxies that miss the charting and slice-cutting steps. Whole-run blocks can be derived only where the run had one item in flight and every wait sat inside that item's ledger; waits outside items (frontier cards before 2.x, questions put in the session such as "which slice next?" or "close the run now?", the lead's between-item time) and usage limits outside item transcripts were never captured, and the lead's own work cannot be told from idle time. The result is four usable single-item runs spread one per series and none in the current series, so a fresh run without the discipline has to be measured first. The minimum new capture: (1) `started:` written on every run start, with no path that skips it (a resumed or reopened map section included); (2) a run-level Waits list in the map's Factory run section for waits outside any item (kind, start, end), fed by the same needs-you `Asked:`/`Answered:` lines and by a `cut-offs.sh` scan of the lead's session transcript over the run's span; (3) at close, a computed `held run` per interval (no item's role task open and no unheld item wait), so whole-run blocks are derived from the item ledgers plus the run-level list rather than stored twice. Run close needs nothing new: the A3's `created_at` is it.
