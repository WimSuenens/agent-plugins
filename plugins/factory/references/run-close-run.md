# Run skill: closing the run (step 9)

Read this when the backlog is empty, the budget is reached or the person stops the run. It is part of the run skill; the text below moved out of `skills/run/SKILL.md` unchanged, and the pointer in the router for any heading says which file holds it. Here `${CLAUDE_PLUGIN_ROOT}` is not substituted (only the router is): read it as the path on the `Plugin root:` line of `skills/run/SKILL.md`, and write that path in every shell command.

## 9. Close the run

Entered when the backlog is empty, the budget is reached (step 8.11) or the person stops the run. [a3.md](${CLAUDE_PLUGIN_ROOT}/references/a3.md) and [baseline.md](${CLAUDE_PLUGIN_ROOT}/references/baseline.md) hold the rules. In this order; no other batch step gathers findings at the end of the run:

0. **Entry.** When the person stopped the run, ask once: `Close the run now? That posts the A3 and settles the overrides.` Silence, a timeout or an assumption is no yes. On no, write nothing: a later run start finds the unanswered overrides and settles them (*Settle round*). The question is a `person` row of the Run waits table (`references/hansei.md`, section 8): write it with `run-state.sh add-run-wait` when the answer is read, before 9.1. On yes, run 9.1 to 9.5, with the A3's `run:` line reading `run stopped`. A closed item counts; an item in flight does not (its worktree stays, resumable with `/factory:run #<slice>`, and the report says so). When the map dissolved, carry on.
1. **Update the current section from the records.** The recomputation of `references/baseline.md`, section 8.1. When the page is unchanged, say `baseline unchanged`.
2. **Write the experiment's before/after reading and post the A3** (`references/a3.md`), with the run's timing first (`references/hansei.md`, section 8), in this order, whatever `docs/agents/factory.md` says:
   a. Stamp the close: `date -u +%FT%TZ`.
   b. The run-close scan: for each id that `bash "${CLAUDE_PLUGIN_ROOT}/scripts/run-state.sh" lead-sessions <body file>` prints, the transcript `~/.claude/projects/<project>/<id>.jsonl`; run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/cut-offs.sh" --until <the stamp> [--sleep-log -] -- <those transcripts>` (the pmset filter of `hansei.md`, section 1, where `pmset` exists) into a scratch file. No `--since`: `cut-offs.sh` keeps a gap only when it starts at or after `--since`, so a gap that began before `started:` would be lost; `run-timing.sh gaps` clips every line to the run window instead. On exit 3 or 4, when `lead-sessions` reads `none yet` or empty or exits 3, or when `lead-sessions` exits 2 (an id not in its format), the A3's line reads `- run timing: not captured (<reason>)` with `lead transcript <basename> unreadable`, `jq missing`, `no lead session recorded` or `lead sessions line not in its format`, and c and d are skipped.
   c. `bash "${CLAUDE_PLUGIN_ROOT}/scripts/run-timing.sh" gaps --run-body <body file> --close <the stamp> --ledger <each item's ledger> -- <scratch file>`; each output line (`<kind>`, `<start>`, `<end>`, `<what>`, tab-separated) becomes one `run-state.sh add-run-wait <body file> --kind <kind> --start <start> --end <end> --what '<what>'`, the fourth field in single quotes (it holds spaces, and the markers grammar admits no `'`); scan the body and post it once (`gh issue edit <run ticket> --body-file`).
   d. `run-timing.sh line`: `bash "${CLAUDE_PLUGIN_ROOT}/scripts/run-timing.sh" line --run-body <body file> --close <the stamp> [--lite] --ledger <each item's ledger>` on the body as just posted; its line is the A3's `run timing` line, pasted verbatim (exit 5 prints the `not captured` line, which is pasted too). `--lite` when an item of the run closed without its close scan (`hansei.md`, section 8).
   e. After *Post A3*, read the comment's `created_at`, run d again with `--close <created_at>`; when the line differs, run the check and *Edit A3* that line. The rows of c are not rewritten.

   The items are those of `run-state.sh items` and the `in flight` line; find each ledger with *Find ledger* and save its body to a scratch file (an item without one is the `not captured` case of `run-timing.sh`). With the `run timing` line, write `- discipline: off`, `run compared` and `guardrails` (`references/a3.md`, section 2.3).

   Then the problem (section 4), the targeted walk (`hansei.md`, section 6, *The targeted walk*), the readings (sections 6 and 7), the lines (section 2), the events lines (section 2.2: run `bash "${CLAUDE_PLUGIN_ROOT}/scripts/a3-events.sh"` over the records of every item and `intake.sh filed-since <run start> <run end> --state all`, paste its output, and add only the cause of each event), run the check (section 9, `bash "${CLAUDE_PLUGIN_ROOT}/scripts/a3-check.sh" <file>`), scan it (*Scan before posting*), then *Post A3*. The A3 posted is v4 (`<!-- factory:a3 v4 -->`); a v1, v2 or v3 A3 found by *Find A3* is left as it is, except that a v2 or v3 one is rewritten on an interrupted close as `references/a3.md`, section 1 says. When the run closed no item (the Factory run section's `closed in this run` line is absent or empty), say `0 items closed: nothing to measure`, post nothing, and go on to 9.3: the overrides still need their answers.
   After the A3 is posted, write its comment URL as the `- A3:` line of the Factory run section (the run skill's *Run identity*): that line is what marks the run closed (to repair the A3 afterwards, pass `--allow-closed` to `a3-events.sh`).
3. **The settle round** (`## Andon`, *Settle round*): the lines carry the A3's before, target and after. After the settle merge, recompute the baseline again (section 8.1).
4. **The feedback offer.** Ask the person what felt clumsy, before drafting. Then draft a factory issue for `WimSuenens/agent-plugins` **only for what the A3 lists, plus the person's remark**: the A3's `standard changes proposed` entries (plugin changes an andon proposed, and `other` (kind 7) abnormalities), the A3's `problem` and `other problems seen`, and the person's remark. Each draft states why it is listed (`listed because: standard change proposed | other abnormality A<k> | the A3's problem | other problem seen | the person's remark`). What the A3 does not list (briefs that came back `blocked` for an input the protocol should have named, a role that did another's work) stays in the project's hansei and andon records and is not drafted. Each draft holds the problem in factory terms, the exact standard change, the before and after figures from the A3 against the baseline with the item count and the release, and a neutral kind of work (the `kind of work` clause of `still uncertain`). It holds no code, no project names, no business content and no raw hansei records. A promoted override's plugin change is not drafted until its decision card is decided. Show the drafts and post only those the person approves (check each draft first with `improvement.sh check`, *Improvement loop*):

   Draft only factory text. A problem or other problem seen is drafted only when its target is a path under the factory plugin's own folder (or a section of such a file) or, in the measure branch, a field name of the baseline; a project path or a bare line target stays in the project's A3. Quote a reading as `<value> (<k> of <n>; factory <semver>)`: leave out the A3's item numbers and every link. A draft holds no `#<n>` form, URL or project path; reason texts are paraphrased, not quoted.

   `gh issue create --repo WimSuenens/agent-plugins --label plugin:factory --title "$title" --body-file "$rec"` (the approved title and body in scratch files, scanned first, *Scan before posting*; `title="$(cat <title file>)"`)

   This is the only instruction that names `--repo WimSuenens/agent-plugins`. Everything else you measure or record, the ledger, the hansei record, the baseline and the A3 included, stays in the project's own tracker and `work/<id>/`.
5. **Report the run closed** and set the map card `Backlog` (the map waits for new ideas; it is not finished), with the A3's link, the baseline's link, the outcome of each override and the link of each open decision card. Do not report the run closed before 9.3 has an answer, applied and merged, for every override of the run.

**Done when** every override of the run has an answer applied and merged, or the run has none; the A3 is posted (or the run closed no item); the person has approved, edited or declined every draft; and the run is reported closed.
